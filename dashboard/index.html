1.1
A THRESHOLD AND A MEASUREMENT MUST SHARE A UNIT — and 'tokens' is not a unit until the tokenizer is named. The governance OS denominates its file-size read-contracts in the token count reported by the reading harness, while a separate write-time budget gate denominates in a public byte-pair encoder. Measured on one file at one instant, the two disagree by a factor of 1.52. Consequence: the primary cross-session knowledge file measured 48.3K under the encoder and read as comfortably under its ~60K cap — SWEEP NOT NEEDED — while its true figure in the cap's own unit was ~73.6K, over by 23%. The uncalibrated reading returned the flattering answer on the exact file the ritual exists to bound. Fix is doctrine, not tooling: state the tokenizer beside any token figure, and when a cap and a measurement come from different instruments, calibrate on a file with a known reading in BOTH units before comparing. One calibration file converted an unverifiable number into a decision-grade one. This is a defect in the UNIT rather than the arithmetic, so re-measuring the value confirms it forever.

1.2
A RELOCATION VERIFIED ONLY AT ITS DESTINATION IS INDISTINGUISHABLE FROM A COPY. The prior month's housecleaning sweep recorded three phases and a precise relocation count. Twenty of those entries were still live — present verbatim in BOTH the live knowledge file and the retrieval-only history file, simultaneously, for two days and across a governance version bump. The sweep asserted arrival and never asserted departure. Both files read as entirely correct in isolation: history holds what it claims, live holds real entries. Only the INTERSECTION is wrong, and no per-file check reads an intersection. Aggravator: the duplication silently inflated the very size measurement that triggers the next sweep, so the instrument that detects the condition was corrupted by the condition. Fix: a move is TWO assertions — present-in-target AND absent-from-source — plus an explicit empty-intersection check. Cost of the check is a single set-comparison command.

1.3
A CLASSIFIER THAT PASSES EVERYTHING IS NOT A LENIENT TEST, IT IS NOT A TEST. To decide which knowledge entries had reached a governance rule, distinctive words from each entry headline were scored against the rules corpus. The classifier returned PASS on 21 of 21 candidates, and its hit-column tracked its word-column almost exactly — the signature of a saturated matcher. Negative control: the sentence 'A PURPLE ELEPHANT CANNOT VALIDATE A SANDWICH' also scored PASS. Against a ~475KB corpus of governance prose, essentially any governance vocabulary appears somewhere. Had the sweep run on that table it would have relocated entries that never reached a rule, which the retention doctrine explicitly forbids. The instrument that WORKED was structural rather than lexical — does the cited rule section contain the entry's catalyst date — and it earned trust by returning a NO on one section while its positive control passed. Rule: before trusting a classifier, feed it something that MUST fail; if it passes, the instrument is the finding.

A COUNTER THAT COUNTS FIRES WAS READ AS A COUNT OF TURNS — BY THE AUTHOR, INSIDE THE AUDIT, AGAINST AN OPEN ITEM THAT ALREADY SAYS SO. The response-discipline hook reported a rising 'session miss-count' that reached 34, and it was written into this sidecar and the private retro as 28-29 consecutive missed turns. It is not. Derived from the firelog with positive and negative controls, all 33 blocking fires carry a SINGLE distinct prior-turn signature, i.e. ONE completed turn missing its marker, graded once per tool call across a long agentic run. Post-compaction exactly two turns completed: one carried the marker, one did not. The true figure is 1 missed turn, not 33. The instrument is behaving exactly as designed and documented; the defect was entirely in the reading. Aggravators worth recording: (a) an open blocker on this very board already states that this counter counts FIRES rather than TURNS, (b) the trace template warns in writing that counting prose blocks against this firelog manufactures a phantom miss count and cites a prior session that did it, and (c) the wrong number was the SELF-CRITICAL one, so it passed review unchallenged in a way a flattering number would not have. Caught only by following the template instead of authoring from memory. Net: discipline was 1 miss; the finding is the misreading.

Meta-finding
Nine measurement instruments used during this retro each failed silently at least once. Eight failed FLATTERINGLY — toward "no work required" or "everything already qualifies" — and the ninth failed in the SELF-CRITICAL direction, which is why it survived longest and reached two artifacts before being caught. A keyword classifier scored a deliberately nonsensical control sentence as a pass. A token measurement compared two different tokenizers and understated a file by 34%. A shell pipeline masked a validator's exit code and nearly produced a false report that a live commit gate was fail-open. A display pipe truncated a finding to half its true size, and the halved number was stated aloud before it was corrected. A rendering fix looked correct in the file and deleted the finding from eight rendered rows. The general form: an instrument's silence, or its agreement with what you hoped, carries no information — only a control that CAN fail tells you the instrument is alive.
